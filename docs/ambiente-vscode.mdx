# Configurando o VS Code para o Stack React-PDF + SQLite + Docker

Este guia mostra como deixar o **Visual Studio Code** pronto para trabalhar com o stack:

- Node.js + `better-sqlite3`
- `@react-pdf/renderer`
- Multi-stage Builds
- Nginx
- Docker + Docker Compose

:::info
Recomendado usar o perfil `docker` criado no tutorial principal.
:::

---

## 1. Criar / usar o perfil `docker`

Se ainda não criou:

```batch
code --profile docker
```

Ou pela interface:

1. `Ctrl + Shift + P`
2. **Profiles: Create Profile**
3. Escolha **Empty Profile**
4. Nome: `docker`

Sempre abra o projeto com o perfil:

```batch
code . --profile docker
```

---

## 2. Extensões recomendadas

Instale todas de uma vez pelo CMD:

```batch
code --profile docker --install-extension ms-azuretools.vscode-containers
code --profile docker --install-extension docker.docker
code --profile docker --install-extension dbaeumer.vscode-eslint
code --profile docker --install-extension esbenp.prettier-vscode
code --profile docker --install-extension bradlc.vscode-tailwindcss
code --profile docker --install-extension qwtel.sqlite-viewer
code --profile docker --install-extension mxrch.vscode-sqlite
code --profile docker --install-extension formulahendry.code-runner
code --profile docker --install-extension christian-kohler.path-intellisense
code --profile docker --install-extension usernamehw.errorlens
```

### O que cada extensão faz

| Extensão                    | Função principal                                      |
|----------------------------|-------------------------------------------------------|
| **Container Tools**        | Gerenciar containers, imagens, volumes e Compose      |
| **Docker DX**              | Linting avançado de Dockerfile e Compose              |
| **ESLint**                 | Análise estática de JavaScript/JSX                    |
| **Prettier**               | Formatação automática de código                       |
| **SQLite Viewer**          | Visualizar e consultar arquivos `.db`                 |
| **SQLite**                 | Outra opção para explorar bancos SQLite               |
| **Error Lens**             | Mostra erros e warnings inline                        |
| **Path Intellisense**      | Autocompletar caminhos de arquivos                    |
| **Code Runner**            | Executar scripts rapidamente                          |

:::tip
As extensões **SQLite Viewer** e **SQLite** permitem abrir o arquivo `data/app.db` diretamente no VS Code e rodar queries.
:::

Crie a pasta `.vscode` na raiz do projeto e adicione os arquivos abaixo.

### `.vscode/settings.json`

```json
{

    "source.fixAll.eslint": "explicit"

  "files.trimTrailingWhitespace": true,

  "javascript.updateImportsOnFileMove.enabled": "always",
  "typescript.updateImportsOnFileMove.enabled": "always",
```

## 4. Configuração do ESLint + Prettier

### Instalar dependências de desenvolvimento

```batch
npm install -D eslint prettier eslint-config-prettier eslint-plugin-react
```

### `.eslintrc.cjs`

```js
module.exports = {
  env: {
    node: true,
    es2022: true,
  },
  extends: [
    'eslint:recommended',
    'plugin:react/recommended',
    'prettier',
  ],
  parserOptions: {
    ecmaVersion: 'latest',
    sourceType: 'module',
    ecmaFeatures: {
      jsx: true,
    },
  },
  settings: {
    react: {
      version: 'detect',
    },
  },
  rules: {
    'react/react-in-jsx-scope': 'off',
    'react/prop-types': 'off',
    'no-unused-vars': ['warn', { argsIgnorePattern: '^_' }],
  },
};
```

### `.prettierrc`

```json
{
  "semi": true,
  "singleQuote": true,
  "trailingComma": "es5",
  "printWidth": 90,
  "tabWidth": 2
}
```

### `.prettierignore`

```
node_modules
output
pdfs-gerados
data
*.db
```

## 6. Trabalhando com o banco SQLite no VS Code

1. Instale a extensão **SQLite Viewer**
2. Clique com o botão direito no arquivo `data/app.db`
3. Escolha **Open Database**
4. Explore tabelas, rode `SELECT` e verifique os dados

:::tip
Sempre valide os dados no VS Code antes de rodar o build Docker. Isso evita falhas desnecessárias no estágio de geração.
:::

## 7. Fluxo de desenvolvimento recomendado

### Desenvolvimento local (sem Docker)

```batch
npm install
node src/generate.js
```

Os PDFs serão gerados em uma pasta local (ajuste o `OUTPUT_DIR` se necessário).

### Testar o build completo

```batch
docker compose up --build -d
```

### Ver logs do container

```batch
docker compose logs -f
```

### Abrir shell no container

```batch
docker compose exec pdf-server sh
```

## 8. Atalhos e dicas de produtividade

| Ação                              | Atalho / Comando                          |
|-----------------------------------|-------------------------------------------|
| Abrir Command Palette             | `Ctrl + Shift + P`                        |
| Rodar task de build               | `Ctrl + Shift + B`                        |
| Formatar documento                | `Shift + Alt + F`                         |
| Abrir terminal                    | `` Ctrl + ` ``                            |
| Ir para arquivo                   | `Ctrl + P`                                |
| Ver containers (Container Tools)  | Ícone de containers na barra lateral      |
| Abrir banco SQLite                | Clique direito no `.db` → Open Database   |

:::tip
Com a extensão **Container Tools** você pode fazer build, start, stop, ver logs e attach shell com o mouse, sem digitar comandos.
:::

## 9. Checklist final do ambiente

Antes de começar a desenvolver, confirme:

- [ ] Perfil `docker` criado e ativo
- [ ] Extensões instaladas (Container Tools, Docker DX, ESLint, Prettier, SQLite Viewer)
- [ ] Terminal padrão definido como **Command Prompt**
- [ ] Arquivos `.vscode/settings.json` e `extensions.json` criados
- [ ] ESLint + Prettier configurados
- [ ] Consegue abrir e consultar o arquivo `data/app.db`
- [ ] `docker compose up --build` funciona sem erros
